Labels: CONFIRMED (reproduced), INFERRED (read from code), HYPOTHESIZED, RULED OUT (checked and fine).

## 0.2.1

Base: 643dcdd (0.2.0 and its post-release records, on main). Closes RS-A-claudewrite and RS-A-fromlabel.

- The copy command in both skills writes the template under a random name beside the target and gives it the target's name with a hard link (`linkSync`), which fails on anything at that name (`EEXIST`) and follows no link. On any other link error it renames the file into place, which writes through no link but replaces a plain file made at the name in that instant. Codex's Windows sandbox refuses the hard link (`EPERM`), so Codex uses the rename. A probe showed why the 0.2.0 create-only write wasn't enough: on Windows it follows a dangling file link and makes an empty folder through a dangling junction. The command also refuses a source or folder that is a link, a source with a second name, and a source or folder that changes between the look and the read (inode and device compared, the source and its folder looked at again after the read), a target folder that is not a folder, and names any random-name file it can't remove. Last, it checks that the target is the very file it wrote (the inode of the handle it wrote through, one name). The Claude Code skill writes templates into a random staging folder (`mkdtempSync`) and uses the same command.
- `--check` keeps only the 50 messages it prints, and makes none for a bad `From:` name past them. On 465,000 bad `From:` names, the old script needs 256 MB of heap and the new one 40 MB on Node 26 (128 MB on Node 18, where the old one also needs 256 MB).

Fail-before runs: the heap test (192 MB since round 11; it was 96 MB, too little for the new script on Node 18) fails on the 0.2.0 script (out of memory) and passes on the new one. On the 0.2.0 skills, 13 of the new copy tests fail, among them the dangling junction made after the check (an empty folder appeared where it pointed). One of them, the file made at the target after the look, fails there only on its message: 0.2.0 kept the file. It guards round 1's rename-only command, which replaced it. Two pass on both: the one-name test and the rename fallback, which guard the new design. Tests added for a mutant rather than a fix were each run on that mutant and failed there. The laziness test fails on the 0.2.0 script and on a mutant that builds every message and drops it. The dangling file-link test, run elevated, passed on both the old and the new command, against a direct probe in which the create-only write wrote through such a link: RS-H-oldrace.
